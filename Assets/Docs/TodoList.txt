프로젝트의 기존 퀘스트 시스템 틀은 유지하고,
아래 요구사항만 반영해서 확장/수정해줘.

퀘스트 시스템 요구사항:

1. 퀘스트는 메인 퀘스트와 서브 퀘스트로 구성된다.
- 메인 퀘스트는 기본적으로 처음부터 존재한다.
- 단, 메인 퀘스트도 특정 조건에서는 잠길 수 있다.
- 서브 퀘스트는 처음부터 전부 보이지 않고, 특정 조건을 만족했을 때 해금된다.

2. 서브 퀘스트 해금 조건 예시:
- 메인 스토리를 특정 단계까지 진행했을 경우
- 특정 장소에 갔을 경우
- 특정 아이템을 얻었을 경우

3. 메인 퀘스트 잠금/해금 조건 예시:
- 특정 서브 퀘스트를 완료해야 진행 가능
- 특정 아이템을 가지고 있어야 진행 가능
- 특정 스토리 조건을 만족해야 진행 가능

4. 메인 퀘스트와 서브 퀘스트는 완전히 분리된 시스템이 아니다.
- 서로의 진행도, 완료 여부, 아이템 보유 여부, 장소 방문 여부를 조건으로 참조할 수 있어야 한다.
- 즉, 두 퀘스트 타입은 유기적으로 연결되어야 한다.

5. 퀘스트 UI:
- 원신의 퀘스트 UI처럼 스크롤 가능한 리스트 형태로 표시한다.
- 해금된 퀘스트가 퀘스트 UI 창의 스크롤 리스트에 추가된다.
- 리스트의 퀘스트 탭을 클릭하면 상세 패널이 열린다.

6. 퀘스트 상세 패널에는 아래 정보가 표시되어야 한다.
- 퀘스트 상세 내용
- 얻을 수 있는 아이템/보상 정보
- 현재 퀘스트 진행도
- 퀘스트 수락 또는 진행 버튼

7. 퀘스트 수락 시:
- 메인 UI의 퀘스트 트래커 내용이 수락한 퀘스트 설명으로 변경된다.
- 퀘스트 트래커 아래에 현재 진행도가 표시된다.

8. 퀘스트 트래커 예시:
- “아린 만나기”
- “숲 입구로 가기”
- “고대 열쇠 찾기 0/1”
- “경비병에게 편지 전달하기”

9. 구현 시 주의:
- 기존 퀘스트 시스템 구조와 public API는 최대한 유지한다.
- 기존 클래스/필드/이벤트 이름을 임의로 바꾸지 않는다.
- 필요한 기능만 최소 수정으로 추가한다.
- 먼저 현재 코드 구조를 파악한 뒤, 어디를 수정할지 요약하고 구현해줘.
- 구조상 충돌이 있으면 바로 수정하지 말고 먼저 설명해줘.

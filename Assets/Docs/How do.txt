Dead Letter Office - Quest System How do

이 문서는 TodoList의 퀘스트 시스템 확장 사용법을 정리한다.
기존 퀘스트 시스템 구조와 public API는 유지했고, 새 기능은 StoryQuestSO와 StoryQuestListSO 설정으로 사용한다.

1. 기본 구성

필요한 SO:
- StoryQuestSO: 퀘스트 1개 데이터
- StoryQuestListSO: 메인 퀘스트와 서브 퀘스트 목록
- FlagSO: 스토리 진행, 장소 방문, 퀘스트 완료 같은 조건
- CollectibleSO: 아이템 보유 조건
- GameStateSO: 아이템 보유 상태 확인용

씬에 필요한 컴포넌트:
- QuestSystem
- QuestLogUI
- QuestObjectiveHUD

QuestSystem에는 Quest Pipeline에 StoryQuestListSO를 연결한다.
아이템 조건을 쓰는 경우 Game State에 GameStateSO도 연결한다.

2. StoryQuestSO 만들기

Project 창에서 Create > DLO > Quest > Quest를 선택해 StoryQuestSO를 만든다.

주요 설정:
- Type: Main 또는 Sub
- Available By Default: 처음부터 퀘스트 목록에 보일지 여부
- Required Flags: 퀘스트가 목록에 해금되기 위한 FlagSO 조건
- Required Unlock Items: 퀘스트가 목록에 해금되기 위한 아이템 조건
- Required Completed Unlock Quests: 퀘스트가 목록에 해금되기 위한 선행 퀘스트 완료 조건
- Required Start Flags: 퀘스트 수락/진행을 위해 필요한 FlagSO 조건
- Required Items: 퀘스트 수락/진행을 위해 필요한 아이템 조건
- Required Completed Quests: 퀘스트 수락/진행을 위해 필요한 선행 퀘스트 완료 조건
- Completion Flag: 켜졌을 때 퀘스트를 완료로 판단하는 FlagSO
- Title, Area, Objective, Description: UI 표시 텍스트
- Locked Message: 조건 미충족 시 상세 패널에 보여줄 문구
- Progress Format, Progress Current, Progress Required: 진행도 표시
- Rewards: 보상 표시

3. 메인 퀘스트 설정

메인 퀘스트는 기본적으로 처음부터 존재해야 하므로 보통 Available By Default를 켠다.
단, 특정 조건 전에는 진행하지 못하게 하려면 Required Start Flags, Required Items, Required Completed Quests를 설정한다.

예시:
- Type: Main
- Available By Default: true
- Required Completed Quests: 특정 서브 퀘스트
- Locked Message: "먼저 관련 서브 임무를 완료해야 한다."

이 경우 퀘스트 목록에는 보이지만, 조건 충족 전에는 수락 버튼이 잠긴다.

4. 서브 퀘스트 설정

서브 퀘스트는 처음부터 전부 보이지 않아야 하므로 보통 Available By Default를 끈다.
Required Flags, Required Unlock Items, Required Completed Unlock Quests 중 필요한 조건을 설정한다.

예시:
- Type: Sub
- Available By Default: false
- Required Flags: 특정 장소 방문 FlagSO

해당 FlagSO가 true가 되면 QuestSystem이 QuestUnlockedEvent를 발행하고, 퀘스트 UI 목록에 추가된다.

5. StoryQuestListSO 설정

Project 창에서 Create > DLO > Quest > Quest Pipeline을 선택해 StoryQuestListSO를 만든다.

설정:
- Main Quests: 메인 퀘스트들을 순서대로 넣는다.
- Sub Quests: 서브 퀘스트들을 넣는다.

이 SO를 씬의 QuestSystem > Quest Pipeline에 연결한다.

6. 퀘스트 수락과 메인 트래커

QuestLogUI에서 퀘스트를 선택하고 수락 버튼을 누르면 QuestSystem.AcceptQuest()가 호출된다.
수락 성공 시:
- QuestAcceptedEvent 발행
- QuestObjectiveChangedEvent 발행
- 메인 UI의 QuestObjectiveHUD가 Objective와 ProgressText를 표시

트래커 예시:
- 아린 만나기
- 숲 입구로 가기
- 고대 열쇠 찾기
- 진행도: 0/1

7. 진행도 사용

현재 구현은 StoryQuestSO의 Progress Current와 Progress Required 값을 UI에 표시한다.
자동으로 아이템 개수나 플래그 수를 계산하지 않는다.

런타임에서 진행도를 바꾸려면 코드에서 StoryQuestSO.SetProgress(current, required)를 호출한 뒤 QuestLogChangedEvent 또는 QuestObjectiveChangedEvent를 발행한다.

예시:
quest.SetProgress(1, 3);
GameEventBus.Publish(new QuestLogChangedEvent());

수락 중인 퀘스트 트래커까지 바로 갱신하려면 QuestObjectiveChangedEvent도 발행한다.

8. 조건으로 쓸 수 있는 것

스토리 진행 조건:
- 해당 단계에서 FlagSO.Value = true로 설정한다.

장소 방문 조건:
- 장소 트리거 또는 상호작용 지점에서 방문 FlagSO.Value = true로 설정한다.

아이템 보유 조건:
- CollectibleObject가 GameStateSO에 아이템을 추가하고 ItemCollectedEvent를 발행한다.
- QuestSystem은 ItemCollectedEvent를 받으면 퀘스트 해금/수락 가능 상태를 다시 확인한다.

선행 퀘스트 완료 조건:
- 선행 StoryQuestSO의 Completed가 true여야 한다.
- Completed는 내부 completed 체크 또는 Completion Flag로 판단한다.

9. DLO 메뉴를 건드려야 하는지

런타임 퀘스트 기능 자체는 DLO 메뉴를 건드리지 않아도 된다.
이번 확장은 StoryQuestSO, StoryQuestListSO, QuestSystem 설정을 통해 동작한다.

단, DLO > Setup > Rebuild DevScene Main HUD로 UI를 다시 생성하는 경우에는 주의한다.
자동 생성된 HUD가 새 필드인 progress text, lock reason text, action button을 연결하지 않으면:
- 퀘스트 목록과 상세 기본 정보는 계속 동작한다.
- 수락 버튼과 상세 진행도 표시는 보이지 않거나 동작하지 않을 수 있다.

따라서 아래 둘 중 하나를 선택한다.

선택 A - DLO 메뉴 수정 없이 사용:
- 기존 씬의 QuestLogUI에 progress text, lock reason text, action button, action button text를 직접 만든 뒤 Inspector에서 연결한다.
- DLO로 HUD를 재생성하지 않는다면 이 방식으로 충분하다.

선택 B - DLO 자동 생성까지 완성:
- DLOSceneSetupTools의 Quest UI 생성 코드에 progress text, lock reason text, action button을 만들고 QuestLogUI 필드에 연결하도록 추가한다.
- 앞으로 DLO > Setup > Rebuild DevScene Main HUD를 자주 쓸 예정이면 이 방식이 안전하다.

현재 판단:
- "SO List만 추가해서 퀘스트를 구성하는 작업"이라면 DLO 메뉴는 안 건드려도 괜찮다.
- "DLO 메뉴로 HUD를 다시 만들고 바로 수락 버튼까지 보이게 해야 한다"면 DLOSceneSetupTools도 수정해야 한다.

10. 주의사항

- 기존 public API 이름은 바꾸지 않는다.
- GameEventBus 이벤트 이름은 바꾸지 않는다.
- 새 조건은 가능하면 FlagSO, CollectibleSO, StoryQuestSO 참조로 구성한다.
- 문자열 키로 조건을 만들지 않는다.
- 씬 파일은 자동 수정하지 않는다. UI 연결은 Unity Inspector에서 확인한다.
- SO는 런타임 상태가 에디터에 남을 수 있으므로 Accepted 상태는 비직렬화 런타임 값으로만 사용한다.
